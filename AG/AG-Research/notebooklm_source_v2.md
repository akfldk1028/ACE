# 멀티에이전트 팀은 언제 멈춰야 하는가? (확장판)

## 연구 개요

14가지 협력 토폴로지의 종료 역학을 2,000회+ 실험으로 체계적으로 연구한 논문입니다. 이 문서는 **기존 연구 결과 요약 + 2가지 추가 연구 방향**을 포함합니다.

---

## 1. 기존 연구 요약 (2,000회+ 실험 완료)

### 14개 패턴 (6범주)

| 범주 | 패턴 | 에이전트 수 | 학술적 근거 | AutoGen 구현 |
|------|------|-----------|-----------|-------------|
| S | Solo | 1 | single-agent baseline | AssistantAgent |
| A | RR-2/3/4 | 2/3/4 | Chain (Masterman et al., 2025) | RoundRobinGroupChat |
| B1 | Sel-3/4 | 3/4 | Star/Hub-spoke (Masterman 2025) | SelectorGroupChat |
| B2 | Swm-3/4 | 3/4 | Mesh/Swarm (Masterman 2025) | Swarm + Handoff |
| C | Refl-2/3 | 2/3 | Reflexion (Shinn et al., NeurIPS 2024) | RoundRobinGroupChat |
| C | Deb-3/4 | 3/4 | Debate (Du et al., ICML 2024) | SelectorGroupChat |
| D | Pipeline | 5 | 순차 정제 (meta-architecture) | 자체 PipelineTeam |
| D | MoA | 4 | Mixture-of-Agents (Li et al., ICLR 2025) | 자체 MoATeam |

### 5개 실험 + 주요 발견

**Exp01: 비용 비교 (980회)**
- 비용 순위: Solo(1,287) < Swm3(4,196) < RR2(4,759) < ... < MoA(22,333) = 17.4배 격차
- **발견**: Swm-3(3명)이 RR-2(2명)보다 싸다. 에이전트 수 ≠ 비용.
- 스케일링: B1 3→4명 = 1.48배(준선형), B2 3→4명 = 3.17배(초선형)

**Exp02: 품질 궤적 (100회, 276턴 점수)**
- 3가지 궤적: 고원형(RR-3), 정점형(Refl-2, 손실 0.00), 하락형(Debate-3)
- **발견**: Debate는 턴 증가 시 품질 하락 (3.8→3.3). "더 대화 = 더 좋다"는 틀림.
- 품질 히트맵 (패턴 × 과제유형): 기술형에서 refl2=5.0 vs sel3=2.2 (2.3배 격차)

**Exp03: 의미 수렴 (분석)**
- 수렴율: pipe(32%) > B1(26%) > A(16%) > B2(12%) > C(0%)
- 피드백 패턴은 cosine 0.673(최고)인데 수렴 0% → 의미 수렴 종료 불가

**Exp04: 종료 실패 (분석)**
- 3가지 실패: 토큰 폭발(RR-4, 72%), 턴 폭발(Swm-4, 76%), 키워드 실종(MoA, 100%)
- B1/C는 오류 0%. 과제별: 사실형 0%, 기술형 RR-4=100%

**Exp05: ΔU 적응적 종료 (800회)**
- ΔU(t) = ΔQ(t) − λ·ΔC(t). 모든 패턴 1.1~2.4턴 수렴. λ 튜닝 불필요.
- 통제실험: 7/8 패턴에서 역효과. Swm-4만 -70% 절감.
- **발견**: TERMINATE 키워드가 7/8 패턴에서 이미 최적.

### 패턴별 종료 행동 (실측 데이터)

| 패턴 | 평균 턴 | 종료 키워드 | 키워드 성공률 | 오류율 |
|------|--------|-----------|------------|-------|
| Solo | 2.0 | TERMINATE | 100% | 0% |
| RR-2 | ~3 | TERMINATE | 높음 | 8% |
| RR-3 | 4.6 | TERMINATE | 높음 | 23% |
| RR-4 | ~6 | TERMINATE | 낮음 | 72% |
| Sel-3 | 3.7 | TERMINATE | 100% | 0% |
| Sel-4 | 4.2 | TERMINATE | 100% | 0% |
| Swm-3 | 8.8 | TERMINATE | 1~6% | 11% |
| Swm-4 | 26.1 | TERMINATE | 28% | 76% |
| Refl-2 | 3.2 | APPROVED | 100% | 0% |
| Debate-3 | 4.6 | VERDICT | 100% | 0% |
| Pipe | 6.0 | ANALYSIS_DONE→TERMINATE | 100% | 0% |
| MoA | ~8 | (없음) | 0% | 100% |

### 현재 한계점
1. **알고리즘 contribution 부재**: 발견은 있지만 새 알고리즘/모델을 제안하지 않음
2. **실용 가이드라인 약함**: "이 상황엔 이 패턴"을 데이터로 뒷받침 못 함
3. **과제 난이도 축 없음**: 4유형은 있지만 Easy/Med/Hard 그라데이션 없음

## 2. 추가 연구 방향 C: Cost-Aware Topology Selection (비용 예측 모델)

### 핵심 질문
> 멀티에이전트 시스템을 **실행하기 전에**, 토폴로지 특성만으로 비용을 예측할 수 있는가?

### 왜 이것이 중요한가
현재 실무에서 멀티에이전트 시스템의 비용은 **실행해봐야** 알 수 있습니다. 14개 패턴을 전부 돌려보고 비교하는 것은 비현실적입니다. 토폴로지 특성(유형, 에이전트 수, 라우팅 방식)만으로 비용을 사전 추정할 수 있다면, 실행 전에 최적 토폴로지를 선택할 수 있습니다.

### 방법

**Features (입력 변수)**:
| Feature | 설명 | 값 범위 |
|---------|------|--------|
| topology_type | 범주 (one-hot: S, A, B1, B2, C_refl, C_debate, D_pipe, D_moa) | 8개 범주 |
| n_agents | 에이전트 수 | 1~5 |
| max_messages | 최대 메시지 수 | 5~14 |
| has_feedback_loop | 피드백 루프 유무 | 0/1 (Refl, Debate = 1) |
| has_central_router | 중앙 라우터 유무 | 0/1 (B1 = 1) |
| has_handoff | 핸드오프 유무 | 0/1 (B2 = 1) |
| is_multi_stage | 다단계 구조 | 0/1 (Pipe, MoA = 1) |

**Targets (예측 대상)**:
| Target | 단위 | 실무 의미 |
|--------|------|---------|
| total_tokens | 토큰 수 | 직접 비용 (API 과금) |
| turn_count | 턴 수 | 실행 시간 근사 |
| error_rate | % | 안정성 |

**학습 데이터**: 기존 Exp01 2,000회+ (패턴별 20~60회 반복)

**모델 비교**:
| 모델 | 특성 | 장점 |
|------|------|------|
| Linear Regression | 기준선 | 해석 가능, feature coefficient 직접 확인 |
| Ridge Regression | L2 정규화 | 다중공선성 처리 |
| Random Forest | 앙상블 | B2 초선형 스케일링 등 비선형 관계 포착 |

**검증**: 5-fold Cross-Validation, R², MAE, MAPE

### 기대 결과

**Feature Importance 예상 순위**:
1. topology_type (가장 강력 — 범주가 비용의 대부분을 설명)
2. n_agents (에이전트 수, 하지만 범주에 따라 효과 다름)
3. has_handoff (B2의 턴 폭발 여부)
4. max_messages (상한선 효과)

**모델 성능 기대**:
- Linear: R² ~ 0.5~0.6 (선형으로는 B2 초선형 스케일링 포착 불가)
- Ridge: R² ~ 0.5~0.6 (Linear과 유사)
- **Random Forest: R² ~ 0.7~0.85** (비선형 관계 포착)
- RF가 월등하면 → "비용 예측은 비선형 모델이 필수" = 발견

**예측 vs 실측 시나리오 예시**:
| 입력 | 예측 토큰 | 실측 토큰 | 오차 |
|------|---------|---------|------|
| B1, 3명, max=10 | ~7,500 | 7,851 | 4.5% |
| B2, 4명, max=12 | ~12,000 | 13,321 | 9.9% |
| A, 2명, max=10 | ~5,000 | 4,759 | 5.1% |

### 알고리즘 contribution
이 모델은 **실행 전 비용 추정기(pre-execution cost estimator)**입니다:
```
CostEstimator(topology_type, n_agents, max_messages) → predicted_tokens
```
이를 통해 실무자는 여러 토폴로지 후보의 예상 비용을 비교한 후, 가장 비용효율적인 것을 선택할 수 있습니다.

### R²가 낮으면? (실패 시나리오)
R² < 0.5라면 "토폴로지 특성만으로는 비용 예측이 불충분하다"가 됩니다. 이 경우 과제 특성(난이도, 유형)이 비용의 주요 결정 요인임을 시사 → 방향 A의 중요성이 올라갑니다.

## 3. 추가 연구 방향 A: 과제 난이도별 최적 패턴 매칭

### 핵심 질문
> 간단한 과제와 복잡한 과제에 **같은 토폴로지를 써야 하는가**?

### 왜 이것이 중요한가
현재 연구의 가장 큰 실무적 공백입니다. "refl-2가 품질 최고"라는 결론은 있지만, 간단한 사실 확인 과제에도 비용 4배인 refl-2를 쓸 이유가 있는지는 알 수 없습니다. 난이도 축이 추가되면 "이 난이도에는 이 패턴이 최적"이라는 실용 가이드라인이 됩니다.

### 실험 설계

**과제 난이도 3단계**: 같은 주제를 Easy / Medium / Hard로 변형

| 도메인 | Easy | Medium | Hard |
|--------|------|--------|------|
| 열역학(과학) | "열역학 1법칙을 설명하라" | "열역학 1~3법칙을 비교 분석하라" | "열역학 원리 기반 차세대 에너지 저장 시스템을 설계하라" |
| LRU 캐시(CS) | "LRU 캐시의 개념을 설명하라" | "O(1) get/put의 LRU 캐시를 구현하라" | "분산 환경에서 일관성 보장 LRU 캐시를 설계하고 장단점을 논증하라" |
| 로마 제국(역사) | "로마 제국의 멸망 시기를 서술하라" | "로마 제국 쇠퇴의 3가지 원인을 분석하라" | "로마 제국과 현대 미국의 구조적 유사성을 다각도로 논증하라" |
| 특허법(법) | "특허의 정의와 기본 요건을 설명하라" | "소프트웨어 특허의 찬반 논거를 정리하라" | "AI 생성물의 특허 적격성에 대한 법적 프레임워크를 제안하라" |
| 게임 밸런스(게임) | "MOBA 게임의 기본 역할 분류를 설명하라" | "MOBA에서 캐릭터 밸런스 패치의 3가지 접근법을 비교하라" | "100+ 캐릭터 게임의 자동 밸런싱 시스템을 설계하라" |

**난이도 기준**:
- **Easy**: 단순 사실 회상 또는 정의 (Bloom's Taxonomy L1-2)
- **Medium**: 비교/분석/구현 (Bloom's L3-4)
- **Hard**: 설계/논증/창의적 종합 (Bloom's L5-6)

**실험 규모**:
- 5도메인 × 3난이도 = 15개 과제
- 5패턴: solo, swm-3, sel-3, refl-2, debate-3
- 3반복 = **15 × 5 × 3 = 225회**
- 각 실행에서 G-Eval 5점 품질 측정 (Exp02와 동일 방법)

### 측정 지표
| 지표 | 측정 방법 |
|------|---------|
| 품질 (G-Eval) | Claude Sonnet 4.5, 5차원 5점 척도 |
| 비용 (토큰) | 입력+출력 총 토큰 |
| 비용효율 (품질/kT) | 품질 점수 ÷ 킬로토큰 |
| 오류율 | 정상 종료 vs 강제 종료 비율 |

### 기대 결과

**핵심 가설**: 과제 난이도가 높아질수록 멀티에이전트의 품질 우위가 커진다.

| 난이도 | 기대되는 최적 패턴 | 근거 |
|--------|----------------|------|
| **Easy** | Solo 또는 Swm-3 | 단순 사실 확인. 멀티에이전트 오버헤드 정당화 불가. 비용효율(품질/kT) 기준 solo가 최적 |
| **Medium** | Sel-3 또는 Swm-3 | 분석/구현 과제. 여러 관점이 도움되지만 refl-2의 4배 비용은 과도. 비용효율 최적 구간 |
| **Hard** | **Refl-2 필수** | 설계/논증. 비평가 피드백이 논리 결함 포착에 필수. 품질 격차가 비용을 정당화 |

**기대 시각화**:
- **난이도 × 패턴 품질 히트맵**: 3행(E/M/H) × 5열(패턴), 색상으로 품질 표시
- **비용효율곡선**: x=토큰, y=품질. Easy/Med/Hard 별로 Pareto frontier가 다름
- **패턴 추천 매트릭스**: 난이도 → 추천 패턴 → 예상 비용 → 예상 품질

### 방향 C 회귀 모델과의 연결

방향 C에서 학습한 비용 예측 모델에 난이도 225회 데이터를 입력하면:
1. **외부 타당성 검증**: 기존 데이터로 학습한 모델이 새 데이터에서도 예측력을 유지하는지
2. **난이도 feature 추가**: difficulty(E/M/H)를 feature에 추가하면 R²가 얼마나 올라가는지
3. **End-to-End 파이프라인**: 난이도 판단 → 비용 예측 → 토폴로지 추천

### 실패 시나리오
- 난이도별 패턴 성능 차이가 유의미하지 않으면 → "난이도는 토폴로지 선택에 영향 없음" = 쓸 수 없음
- 하지만 Exp02에서 이미 기술형(Hard에 가까움)에서 격차 극대화(5.0 vs 2.2) 확인 → 방향성은 있음

## 4. 통합: 논문의 새로운 Contribution 구조

### 기존 (약함)
1. 벤치마크: 14패턴 교차 비교 (방법론)
2. 발견 1: Swm-3 < RR-2 비용 (놀라운 데이터 포인트)
3. 발견 2: Debate 품질 하락 (기존 상식 반론)
4. ΔU 메트릭: 1/8 패턴에서만 유효 (약함)

### 추가 후 (강함)
1. **알고리즘**: Cost-Aware Topology Selection 비용 예측 모델 (방향 C)
   - "실행 전 비용 추정기" = 새 알고리즘
   - Feature importance 분석 = 토폴로지 비용의 결정 요인 규명
2. **실용 프레임워크**: 난이도별 최적 패턴 가이드 (방향 A)
   - "간단한 건 solo, 복잡한 건 refl-2" = 실무 가이드라인
   - 비용효율곡선으로 투자 대비 품질 최적화
3. **발견**: 비용 위계 뒤집힘 + Debate 품질 하락 (기존)
4. **검증**: 방향 C 모델의 외부 타당성 + 교차 모델 검증

- 기존: "When Should Multi-Agent Teams Stop?"
- 확장 후보: "When Should Multi-Agent Teams Stop, and Which Topology Should They Use?"
