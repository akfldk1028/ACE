```
이 논문을 기반으로 연구 발표용 PPT 슬라이드를 만들어줘.

## 필수 조건
- 한국어
- 흰색 배경
- 각 슬라이드: 제목 + 핵심 포인트 3~4개 + 발표자 노트(대본)
- 모든 수치는 소스 문서의 실제 데이터 사용 (반올림/추정 금지)
- 차트/다이어그램이 지정된 슬라이드는 반드시 해당 시각화 포함
- 정확히 15장 (넘기지 말 것)

## 슬라이드 구성 (15장)

### 슬라이드 1: 제목
- 논문 제목: "멀티 에이전트 팀은 언제 멈춰야 하는가?"
- 부제: 14가지 협력 토폴로지의 종료 역학 체계적 연구
- 2,000회+ 실험, Claude Haiku 4.5 + GPT-4o-mini 교차 검증

### 슬라이드 2: 연구 동기
- 핵심 질문: "이 팀, 언제 멈춰야 하나요?"
- 현재 방법 3가지 (max턴, TERMINATE 키워드, 타이머)의 문제점
- 종료 후회(termination regret): 과잉 / 과소 / 토폴로지 불일치
- 선행 연구 갭: Hu et al.(토론만), REFRAIN(단일만), Aegean(합의만) → 14패턴 교차 비교 = 없었음

### 슬라이드 3: 6개 범주 토폴로지 다이어그램
- 반드시 노드-화살표 다이어그램으로 각 범주를 시각화:
  - S (Solo): [Agent] 단독
  - A (순차 체인): [Researcher]→[Writer]→[Reviewer]→[Researcher]→... 고정 순서 순환
  - B1 (중앙 라우팅): 중앙에 ★[Selector LLM]★, 방사형으로 [Expert A][B][C] 연결. Selector가 매 턴 "다음 누구" 결정
  - B2 (분산 핸드오프): [Triage]↔[Specialist A]↔[Specialist B] 메시형. 각 에이전트가 자율적으로 handoff() 호출하여 다음 에이전트로 직접 전달. 중앙 조정자 없음!
  - C (피드백): [Generator]⇄[Critic] 양방향 루프 (Reflection) / [Advocate]↔[Critic]→[Judge] (Debate)
  - D (복합): [Stage1 팀]→결과→[Stage2 팀] 순차 (Pipeline) / [P1][P2][P3] 병렬→[Aggregator] (MoA)
- 에이전트 수 선택 근거: 2명=최소협업, 3명=표준, 4명=스케일링 비교. 같은 범주 내 n→n+1 확장 효과를 체계적으로 측정하기 위한 그리드 설계

### 슬라이드 4: 실험 설계
- 5개 실험 (효율/품질/수렴/오류/적응적 종료), 2,000회+ 실행
- 25개 과제 x 9개 도메인 x 4과제유형 (사실/분석/기술/창의)
- 에이전트: Claude Haiku 4.5, 평가: Claude Sonnet 4.5 (G-Eval 5차원)
- 교차 검증: GPT-4o-mini 125회 (5패턴 x 25과제)
- 대화 로그: 전체 1,905회 실행의 원문 JSON 보존 (턴마다 에이전트명, 발화 전문, 토큰 수)

### 슬라이드 5: Exp01 — 비용 랭킹
- 차트: 수평 막대 그래프 (차트 5 데이터)
  - Solo(1,287) → swm3(4,341) → refl2(5,281) → ... → pipe(13,186)
- 새로운 비용 위계: A ≈ B2 < B1 ≈ C ≪ D (기존 가정 폐기)
- swm3(3명)이 rr2(2명)보다 12% 저렴 — 라우팅 방식이 에이전트 수를 이김

### 슬라이드 6: B1 vs B2 — 정반대 스케일링 (교수님 요청 #3)
- 다이어그램: B1(Selector)과 B2(Swarm)의 구조를 나란히 비교
  - B1: ★Selector★가 중앙에서 분배 → 에이전트 추가해도 안정
  - B2: 중앙 없이 자율 핸드오프 → 에이전트 추가하면 핸드오프 체인 폭주
- 차트: 이중 비교 막대 (차트 3 데이터)
  - sel3→sel4: 토큰 1.28x (준선형) / swm3→swm4: 토큰 3.37x (초선형)
- 턴당 토큰: B1=2,270~2,538 (긴 독백) vs B2=523~544 (짧은 핸드오프)
- "동적 라우팅"으로 묶으면 안 되고, 반드시 B1/B2로 분리해야 하는 이유

### 슬라이드 7: 도메인(주제)별 분석 (교수님 요청 #2)
- 차트: 히트맵 (차트 2 데이터, 9도메인 x 8패턴)
- 법/정치에서 rr3가 17,444 토큰 (긴 분석), 의학에서 pipe가 29,621 폭발
- debate3만 도메인 불변 (CV=0.14) — 과제가 바뀌어도 비용 일정
- swm3는 역사(1,384) vs 경영(9,163)으로 극단적 도메인 민감 (CV=0.67)
- 과제 복잡도가 비용을 토폴로지와 독립적으로 최대 2배 증폭

### 슬라이드 8: Exp02 — 품질 궤적 3가지
- 차트: 3개 꺾은선 그래프 (턴별 품질 점수)
  - 단조증가-고원: RR-3 (3.9→4.5→4.1)
  - 2턴 정점: Refl-2 (3.9→4.8→4.0) ← 최고 품질 + 제로 품질 손실
  - 단조 하락: Debate-3 (3.8→3.4→3.3) ← 가장 위험
- 종료 후회: Refl-2=0.6턴 vs Debate-3=2.0턴 (13배 차이)

### 슬라이드 9: Exp03 수렴 + Exp04 오류
- 왼쪽: 수렴율 막대 (차트 8) — pipe(32%)>B1(26%)>A(16%)>B2(12%)>C(0%)
- 오른쪽: 오류율 막대 (차트 7) — swm4만 76%, 나머지 0%
- 피드백 패턴(C)은 의미적으로 수렴 안 함 → 품질 기반 종료 필요
- 스웜은 메시지가 6분의 1 길이 → TERMINATE 키워드 출력 자체가 구조적으로 어려움

### 슬라이드 10: ΔU(t) 한계 효용 — 수식과 수렴 (교수님 요청 #1)
- 수식 크게 표시: ΔU(t) = ΔQ(t) − λ·ΔC(t)
  - ΔQ(t): t턴 품질 증분, ΔC(t): t턴 비용(kT), λ: 균형 파라미터
  - ΔU(t) ≤ 0 → "이번 턴의 품질 개선이 비용을 정당화 못함" → 종료
- 차트: 패턴별 ΔU 수렴 턴 (차트 1 데이터)
  - 모든 패턴에서 1.1~2.4턴 내에 ΔU → 0 수렴
  - swm3=1.1턴(가장 빠름), rr3=2.4턴(가장 느림)
- λ 둔감성: λ=0.0~0.5 변경해도 수렴 턴 0.1턴 차이 → 품질 포화(ΔQ≈0)가 지배적

### 슬라이드 11: ΔU 적용 결과 — 역설
- 차트: 비교 표 (기준선 vs ΔU 적응적 종료, 토큰 변화율)
  - 7/8 패턴: 오히려 비용 증가 (+8% ~ +258%)
  - swm4에서만: -70% 토큰 절감 (극적 개선)
- TERMINATE 키워드가 7/8 패턴에서 거의 최적이라는 것 자체가 핵심 발견
- ΔU는 키워드 대체가 아닌, 키워드가 실패하는 스웜의 보조 진단 도구

### 슬라이드 12: OpenAI 교차 검증 (GPT-4o-mini)
- 차트: Claude vs GPT 토큰 비교 표
  - Solo: 1,287 vs 697 / Sel-3: 7,851 vs 3,598 / Swm-3: 4,196 vs 3,203
  - Refl-2: 5,237 vs 5,105 / RR-3: 10,121 vs 14,325
- Spearman ρ = 0.900 (p=0.037) — 상대적 순서 강하게 보존
- 두 모델 모두 동일 결론: Solo < Swm-3 < {Sel-3, Refl-2} < RR-3
- 절대 토큰은 다르지만 토폴로지 의존 역학은 모델 불변

### 슬라이드 13: 대화 로그 분석 (교수님 요청 #4)
- 전체 1,905회 실행의 대화 원문 JSON 보존
- 차트: 패턴별 평균 턴 수 막대 (차트 4 데이터)
  - Solo=2.0 → refl2=3.2 → sel3=3.7 → rr3=4.6 → swm3=8.8 → swm4=26.1(폭발)
- 턴마다 기록: 에이전트명, 발화 전문(content), 타임스탬프, 입력/출력 토큰

### 슬라이드 14: 한계점
- κ=0.244 (평가자 간 일치도 약함, "fair" 수준)
- 교차 모델 n=5 패턴만 (전체 13개로 확장 필요)

### 슬라이드 15: 실무 가이드라인 + 핵심 기여
- 가이드라인 표:
  - 비용 최소화 → Swm-3 또는 Refl-2
  - 최고 품질 → Refl-2 (4.80/5.0, 제로 품질 손실)
  - 예측 가능한 비용 → Debate-3 (도메인 불변, CV=0.14)
  - 대규모 팀 → B1(Selector) 사용. B2(Swarm)는 4명부터 폭발 위험
  - 스웜 사용 시 → 3명 고정 + ΔU(λ≥0.1) 보조 종료 추가
- 핵심 기여: "토폴로지가 종료를 결정한다. 에이전트 수가 아니라 연결 방식이 핵심."
```
