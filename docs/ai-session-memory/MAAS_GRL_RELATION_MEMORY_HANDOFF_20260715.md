# MAAS GRL / Mass-Brain relation-memory handoff

Updated: 2026-07-15

## Read this before changing another mass family

The user requires both directions in one durable system:

- preserve the v98 mixed portfolio: step/terrace, courtyard/carve, ribbon/bend,
  bridge/interlock, fold/roof, cluster/field and oblique envelope;
- add clean, restrained primary-envelope designs without replacing the board
  with boxes or Lego assemblies.

Do not solve this by hard-coding another named precedent or parcel-coordinate
template. GRL is the graph contract/query layer. `D:\Data\Mass-Brain` is the
project memory/recombination service. ARR remains the geometry, VLM, law,
parking and final-selection owner.

## Root defects found

1. GRL exports in ARR were post-hoc audit evidence and did not influence the
   next population.
2. Mass-Brain selected parents mainly by structural distance, attached up to
   six child operations serially and jittered every numeric parameter. This
   directly produced Lego-like assemblies.
3. Learning signatures were only `role:verb`; clean envelope retention,
   operation count, void/ground relation, fragments, surfaces and context were
   absent.
4. SQLite graph versions were append-only, but generation queried only the
   newest envelope, so prior executable languages were not actually retrieved.
5. The program-massing/VLM loop that produced v98 did not call Mass-Brain at
   all. Only the separate legal optimizer had a bridge.
6. A first integration accidentally included shadow sequences in evolutionary
   seeds. v99 card 16 proved that `slots=0` could contaminate the final board.
   This is fixed; never restore that wiring.

## Implemented

Mass-Brain (`D:\Data\Mass-Brain`):

- `src/relation-profile.ts`: coordinate-free relation profile and fingerprints
  for `preserve/carve/step/bend/bridge/cluster/fold`, envelope retention,
  operation/void/ground/component/fragment/surface/proportion/compactness bins
  and program/site context.
- `src/traversal.ts`: relation tokens, compatibility score and behavior-cell
  round-robin; all seven strategies were observed in a 20-proposal service
  integration run.
- `src/recombine.ts`: no blind numeric jitter; max three non-root operations;
  bounded coherent-primary-subgraph plus one contrasting operation; relation
  fingerprint is part of the learned signature.
- `src/store.ts`: bounded `memoryEnvelope()` retrieval merges executable nodes
  from the latest 12 append-only graph versions instead of forgetting them.
- Tests prove relation indexing, fragment incompatibility penalty, 3-4-node
  proposals, parameter preservation and cross-version executable retrieval.

ARR:

- `mass_brain_relation_profile.py` computes the same general relation evidence
  from MassDSL sequences and evaluated geometry.
- `mass_brain.py` preserves parameter-distinct sequences, sends relation/context
  payloads, returns sequence-only shadow proposals for program massing, records
  VLM/outcome relation evidence and blocks weak learning unless the clean-mass
  gate passes: surfaces <= 48, components <= 5, small fragments <= 1, envelope
  retention >= 0.55 and dominant operations <= 3.
- `program_massing/vlm_a2a.py` now compiles and VLM-scores Mass-Brain proposals
  separately. With rollout `shadow/slots=0`, they are excluded from search and
  final selection. Only an independently promoted active rollout may admit at
  most four.
- Live script: `run-maas-v99-relation-memory.py`; set `MAAS_RUN_STEM` for a new
  evidence run. It reuses v98 author/VLM caches before making new calls.
