# 솔직한 평가: 매스 자동화 이 방법이 맞나?

**Date**: 2026-05-06
**질문**: "박스 5개 적층 GA로 매스 자동화하는 이 방법이 진짜 맞는 길인가? 점진 업데이트로 충분한가?"

---

## 🎯 한 줄 결론

> **점진 업데이트로 80% 개선 가능. 그러나 진짜 SOTA로 가려면 *매스 인코딩 자체를 SDF/Diffusion으로 교체*해야 함. 이는 점진이 아닌 *재설계*.**

---

## 📊 업데이트 vs 재설계 매트릭스

### ✅ 점진 업데이트로 가능 (현재 시스템 유지)

| 항목 | 비용 | 효과 |
|------|------|------|
| **매스 알고리즘 추가** (L자, 곡면, 캔틸레버) | 1-2주 | 표현 다양성 ↑30% |
| **Radiance 일조 시뮬레이션** | 2-3주 | "기하 검증"에서 "진짜 채광 품질"로 |
| **Surrogate model** (학습된 빠른 평가) | 1개월 | GA 평가 비용 100배 ↓ |
| **NSGA-III** (pymoo 통합) | 3일 | many-objective(4+) 확장 |
| **LLM Agent + 건축 사례 RAG** | 2-3주 | 사용자 가이드, 사례 학습 |
| **MOEA/D** (분해 기반 다목적) | 1주 | 더 균등한 Pareto 분포 |

→ 누적 작업 약 2-3개월. *시스템은 그대로*, 성능 80% ↑.

### ❌ 점진 업데이트 *불가능* (재설계 필수)

| 항목 | 비용 | 이유 |
|------|------|------|
| **매스 인코딩 → SDF/Implicit** | 2-3개월 | 박스 적층과 완전히 다른 표현. 평가 함수도 재작성 |
| **Diffusion 모델 학습** | 3-6개월 | 건축 사례 데이터셋 1,000건 + GPU + fine-tuning |
| **Differentiable Rendering** (Mitsuba 3) | 1-2개월 | 평가 파이프라인 새로 짜야. gradient flow 가능 |
| **Constraint-aware Generation** | 학습 기반 | 법규를 hard constraint로 학습 단계에 주입 |

→ 박스 적층 *그대로 두고 옆에 새 트랙* 만들어야 함.

---

## 🛤 합리적인 3단계 로드맵

### 단계 1 — *지금 바로* (1-2주)
**현재 시스템에 NSGA-III + Radiance 통합**
- 발표 후 즉시 시작
- 코드는 그대로, 평가/탐색만 강화
- 효과: many-objective + 진짜 채광 품질

### 단계 2 — *2-3개월 내* (점진)
**LLM Agent + 사례 RAG + Surrogate**
- ARR/AG 인프라(이미 존재) 활용
- LLM이 *건축 사례*로 GA 가이드
- Surrogate가 *법규 평가* 100배 가속
- 효과: 시스템이 *경험을 누적*하기 시작

### 단계 3 — *6개월~1년* (재설계 트랙)
**SDF/Diffusion 매스 + Differentiable Rendering**
- 박스 적층은 *deprecated*, SDF가 메인
- Mitsuba 3로 일조 미분 가능 → gradient descent
- Diffusion model이 *건축 사례 학습* → 자유 형태 매스
- 효과: 학계 SOTA 진입

## 🎯 가장 솔직한 권장

### "업데이트로 충분한가?" — **No.**
박스 적층 GA는 *2010년대 SOTA*. 점진 업데이트로 ~3년치 격차를 메울 수는 있지만, 학계 *최전선*에는 못 따라감.

### "그럼 다 갈아엎어야 하나?" — **부분적으로 Yes.**
*시스템 통합* 은 유지. *알고리즘과 매스 표현* 만 단계적으로 교체. 박스 적층은 *MVP / 한국 법규 빠른 검증* 용으로 남겨둘 수 있음.

### "지금 가장 먼저 할 일 하나만 추천" — **NSGA-III + Radiance 통합 (3-4주)**
이 한 작업이 *효과 대비 비용* 가장 좋음. 코드 변경 작고 효과 큼. 이걸 먼저 하면서 SDF/Diffusion 재설계는 *연구 트랙*으로 별도 운영.
