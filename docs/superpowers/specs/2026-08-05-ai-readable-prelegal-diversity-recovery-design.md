# AI-Readable Pre-Legal MASS Diversity Recovery Design

**Date:** 2026-08-05

## Goal

Restore a same-PNU board of twenty materially different, LLM-authored,
compiler-clean pre-legal MASSes while making the existing production path easy
for an AI or engineer to follow. The diagnostic may use fresh LLM authorship,
but it performs no paid VLM review and makes no law, parking, capacity, program,
or final-selection acceptance claim.

The target parcel remains PNU `1168011800104170004` and the target program
remains `neighborhood`. A stepped MASS remains valid; a board monopolized by
stepped or near-identical certified meshes is a failed diversity diagnostic.

## Confirmed Regression

The author supply has not collapsed to one family. r87 observations include
`bend_notch`, `split_wing`, `inflate_carve_void`, `cut_corner_notch`,
`twist_lift`, courtyard, shear, cross and stepped programs. The collapse occurs
later: the final visual-selection pool contained two candidates and both were
measured as `stepped`; only one survived final VLM.

Non-stepped supply is lost through authored-to-projected morphology authority,
profiled-mesh canonical revalidation, floor-midplane topology/Hausdorff checks,
and downstream hard gates. Separately, the first fresh replenishment author
request in r84-r87 received HTTP 429, so later cycles had no fresh authored
supply. The selector cannot manufacture diversity after this attrition.

## Scope

This work has two ordered subprojects:

1. Document and enforce the existing module boundaries without changing MASS
   behavior.
2. Run a bounded pre-legal diversity path using those boundaries and record
   exactly where each authored form survives or is rejected.

Large-scale file moves, package renames, law/parking changes, final VLM work,
and the pending symmetric midpoint weld are outside this first diagnostic.
Small function extraction is allowed only when characterization tests first
prove unchanged behavior.

## Existing Modules and Ownership

No new archive, agent, compiler or generation system is introduced.

- `book_language/portfolio_benchmark.py` owns run orchestration, cross-cycle
  state, the invocation-scoped author-rate-limit circuit and artifact summary.
- `book_language/portfolio_replenishment.py` owns bounded replenishment cycles,
  causal feedback, certified reviewed-parent snapshots and live QD reserve
  transitions.
- `book_language/candidate_generation.py` owns LLM program acquisition,
  BASE/BOOK descendant scheduling, canonical materialization and stage outcome
  emission. It remains the production generation implementation.
- `creative_morphology.py` owns the existing pre-legal scale-invariant mesh
  descriptor, pair distance and morphology acceptance decision.
- `book_language/quality_diversity_archive.py` remains the full BOOK legal
  candidate archive. Its `_Candidate` contract is not imported into the
  pre-legal creative command.
- `book_language/run_budget.py` owns author request and compile budgets.
- `book_language/portfolio_selection.py` remains the final portfolio selector;
  it is not used to disguise deficient pre-legal supply.
- `geometry_language/` remains the only AST/compiler/canonical geometry
  authority.

An AI-readable map will identify these owners, the public benchmark entry
point, the pre-legal diagnostic entry point, the typed data crossing each
boundary, and the authoritative tests. Generated PNG/JSON artifacts and
historical memory are explicitly marked as evidence, never executable source.

## AI-Readable Structure Contract

The first structural change is documentation plus import-level boundary tests,
not bulk movement of dirty shared files. The module map must answer:

1. Where does a fresh or cached GeometryProgram enter?
2. Which function compiles and measures the authoritative indexed mesh?
3. Where are cache hits, provider attempts, HTTP 429 and cooldown recorded?
4. Where are certified parents and live QD candidates carried across cycles?
5. Which artifacts are diagnostic-only, and which objects can reach final
   selection?

`candidate_generation.py` is treated as a decomposition target, not replaced.
Only cohesive existing responsibilities may later move behind typed interfaces:
author acquisition/outcome recording, canonical lineage scheduling, and
materialization diagnostics. Each extraction must preserve its old import or
call boundary until callers and focused tests migrate.

## Pre-Legal Diversity Flow

```text
same PNU + neighborhood context
-> cache-first LLM author requests
-> fresh author transport within the run budget
-> typed GeometryProgram validation
-> canonical compile and structural geometry gates
-> authoritative indexed-mesh morphology measurement
-> existing creative-morphology distance retention
-> deterministic twenty-card pre-legal board and evidence bundle
```

The board is composed from actual authored programs and their certified
compiler meshes. Named-family quotas, fixed recipes, coordinate recipes,
candidate cloning, parameter-only jitter and visible stepped fallback are
prohibited. Family names remain post-hoc diagnostics. Retention uses the
existing mesh-derived descriptor/fingerprint machinery so semantic labels
cannot substitute for geometric difference.

## Fresh Author and HTTP 429 Contract

The diagnostic permits at most three fresh author transport attempts and zero
VLM requests. Cache lookup does not consume a fresh-transport attempt.

On the first HTTP 429 in an invocation:

- record a typed provider outcome and activate the existing invocation-scoped
  cooldown circuit;
- defer all remaining author transport attempts in that invocation without
  sleeping or retry storms;
- continue compiling cached programs, already returned fresh programs,
  certified reviewed parents and authorized typed descendants;
- preserve the existing compile and candidate budgets;
- emit a twenty-card board if twenty valid distinct meshes are available;
- otherwise emit an explicit partial board and supply-deficit evidence.

A 429 never permits a fixture recipe, duplicated mesh, invented candidate,
relaxed geometry gate or forced stepped replay. Cross-invocation retry timing
is evidence and policy input; it does not silently turn a failed provider call
into authored supply.

## Diversity Evidence and Acceptance

The diagnostic succeeds only when all twenty cards:

- come from valid LLM-authored GeometryPrograms, including legitimate cached
  author responses;
- compile through the unchanged canonical geometry compiler;
- are connected, watertight and manifold under existing gates;
- have distinct authoritative geometry hashes;
- pass the existing mesh-fingerprint near-duplicate check; and
- are retained without named-form quotas or stepped fallback.

The artifact must report generation, compilation, structural pass and archive
retention counts by measured phenotype, body, section and plan descriptors.
It must also report `visible_stepped`, pyramidal and wedge counts, duplicate
pairs, provider attempts, cache hits, 429 outcomes, cooldown deferrals and the
immediate rejection reason for every omitted authored program.

Success does not require a fixed number of triangular, disc, courtyard,
split-wing or other named families. It does require that the certified-mesh
descriptor and pair-distance evidence reject a stepped-only or geometrically
repetitive board.

## Artifact Contract

One immutable output directory contains:

- the twenty-card board or explicit partial board;
- one manifest with the command, PNU, program, runtime and request budgets;
- each retained GeometryProgram and program/geometry hash;
- provider/cache/cooldown outcomes;
- stage and morphology histograms;
- near-duplicate pair evidence; and
- a machine-readable rejection ledger.

The board and manifest are labeled `PRE-LEGAL / NOT LAW, PARKING, CAPACITY OR
VLM ACCEPTED`.

## Verification Strategy

1. Characterize the current author/cache/cooldown and cross-cycle reserve
   behavior before extracting any code.
2. Force a synthetic first-call HTTP 429 and prove later transports are
   deferred while cached/carried candidates continue through compilation.
3. Prove a supply deficit produces an explicit partial result without fallback
   or duplication.
4. Use deterministic authored fixtures to prove the archive retains genuinely
   different certified meshes and rejects label-only or parameter-jitter
   duplicates.
5. Run focused existing candidate-generation, replenishment, budget, archive,
   morphology-preservation and benchmark tests.
6. Run one bounded same-PNU fresh-author diagnostic with at most three author
   transports and zero VLM calls.
7. Compare its stage/phenotype histograms and board directly with r87 and the
   prior diverse pre-legal cache-pool evidence.

## Failure Handling

- Provider unavailable or 429: continue safe local supply and return explicit
  partial evidence if twenty cannot be reached.
- Invalid author response: typed rejection; no repair by prose guessing.
- Compiler or structural failure: preserve the program and exact gate codes;
  do not place it on the board.
- Repetitive supply: fail the diversity diagnostic even when twenty meshes
  compile.
- Dirty-worktree dependency: isolate task-only patches and stop before staging
  if a change depends on unrelated uncommitted hunks.

## Explicit Non-Claims

- This is not a legal, parking, capacity, program-fit or final-VLM acceptance.
- Twenty pre-legal cards are not a competition-grade portfolio.
- HTTP 429 resilience does not guarantee fresh supply from an unavailable
  provider.
- Structural reorganization does not authorize deleting historical evidence or
  moving unrelated user work.
- The symmetric midpoint weld remains a separate canonical-repair task.
