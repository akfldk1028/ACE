# Full BOOK Production Recovery Design

## Goal

Restore the creative MASS production path so cached and freshly authored LLM
programs obey the same canonical `UnitBox -> Matrix4 BaseVolume -> BOOK scope
and sentence -> recursive architectural geometry` contract as the verified
BOOK language system. Preserve the deterministic 100-candidate lane as a
fixture and diagnostic, not as production authorship authority.

## Current failure

persisted authored layer contains no materialized BOOK scope, base operative,

## Authority model

The normalized `1/1 UnitBox` is the sole primitive Base Model authority.
Every authored candidate must have exactly one canonical UnitBox node.

The evaluated affine BaseVolume is the UnitBox transformed by an explicit,
composed homogeneous 4x4 matrix. Persisted normalized production ASTs may not
use `scale`, `rotate`, `translate`, `reflect`, or `shear` shorthands as affine
authority. Those operations lower into Matrix4 nodes before topology-changing
architectural operations.

BOOK `1/1`, `3/8`, `1/2`, `1/4`, `1/8`, and `1/16` are derived scope states of
the evaluated BaseVolume. They are not sibling primitives or completed form
templates. A materialized scope node records the fraction, orientation, host,
and derivation lineage.

Matrix4 cannot change topology. Void, branch, bend, split, intersection,
continuous section, plate, shell, bridge, pattern, sweep, loft, and composition
remain typed recursive operations whose inputs ultimately descend from the
single UnitBox.

## Production language supply

The canonical BOOK registry remains the only taxonomy source:

- 30 base operations;
- 20 combinations;
- 9 aggregations;
- 10 case-study compound-language evidence records.

A deterministic production scheduler enumerates registry-backed principle
lineages independently of LLM cache order. It assigns one lineage and one of
the six scopes to each authored source attempt. The scheduler is reproducible,
balanced by scope, and exhaustive before repeating a principle.

The LLM remains the geometry author. BOOK projection wraps or derives from the
authored BaseVolume and may not erase the authored root silently. Named
creative families remain fixture labels or post-hoc morphology labels; they
are not production quotas.

For a twenty-candidate pre-legal diagnostic, retained supply must contain all
six scopes and twenty distinct registry principle IDs. For the deterministic
100-candidate fixture, retained supply must cover all 30 base operations, all
20 combinations, and all 9 aggregations at least once. Coverage counts refer
to executable persisted lineage, not metadata labels.

## Capability-range references

Qatar National Library, Seattle Central Library, SANAA, OMA, and Qatar

generic language can express:

- light but positive-thickness plate fields;
- continuous floor-wall-roof sections;
- central or relational public voids;
- tilted, folded, intersecting, and supported slabs or shells;

## Components

### Affine normalization

A focused normalization module converts affine shorthand chains to explicit
Matrix4 nodes, composes adjacent affine transforms in program order, preserves
pivot semantics, rewires consumers, and retains provenance for the original
authored operators. It fails closed on unsupported or non-finite transforms.

Normalization proves:

- exactly one canonical UnitBox;
- at least one BaseVolume Matrix4 descending directly from it;
- no persisted affine shorthands;
- every topology-changing node descends from the evaluated BaseVolume;
- program hash is computed only after normalization.

### BOOK assignment and projection

A focused supply module obtains ordered principle records from the canonical
registry, balances the six scope labels, and applies the existing BOOK
projection compiler to normalized authored programs. The assignment identity
contains source program hash, principle ID, scope label, orientation, and
projection version.

Projection failure rejects only that attempted assignment. It records a typed
stage, code, source identity, principle ID, and scope instead of falling back
to the unprojected source.

### Coverage ledger

The pre-legal report and persisted stage ledger record, for attempted,
compiled, structurally passed, morphology-retained, and rejected candidates:

- UnitBox count and BaseVolume Matrix4 status;
- scope label and orientation;
- principle kind and ID;
- ordered BOOK verbs and aggregation methods;
- topology-changing operator path;
- capability tags such as continuous section, plate/shell, public void,
  bridge/support, interlocking plane, and ordinary solid;
- typed rejection stage and code.

Coverage is evidence, not an acceptance substitute. Hash uniqueness and label
coverage cannot override morphology or geometry gates.

## Data flow

```text
cached or fresh LLM authored AST
  -> canonical UnitBox validation
  -> affine shorthand lowering and Matrix4 composition
  -> evaluated BaseVolume
  -> deterministic BOOK scope and principle assignment
  -> typed BOOK projection
  -> canonical compile
  -> connected/watertight/manifold gate
  -> physical capacity Matrix4 and occupied-floor evidence
  -> hash and morphology gates
  -> pre-legal candidate plus coverage ledger
```

The later PNU law, parking, certified capacity, program, final VLM, and
portfolio selector stages remain unchanged and out of the first recovery run.

## Failure behavior

- Missing or multiple UnitBoxes: typed normalization rejection.
- Unsupported affine shorthand or invalid matrix: typed normalization
  rejection.
- Missing BaseVolume Matrix4: typed authority rejection.
- BOOK projection compile failure: typed projection rejection; never retain
  the unprojected program.
- Scope or principle coverage deficit: report `partial` with exact deficit;
  never relabel the run complete.
- Provider 429: retain the existing invocation-scoped circuit and continue
  with cache supply; no coverage claim may be filled by metadata-only records.
- Fewer than the target survive: emit the partial board and all rejection
  evidence without weakening geometry or morphology thresholds.

## Verification strategy

Implementation follows red-green TDD in sequential checkpoints:

1. Affine normalization tests prove shorthand removal, composed Matrix4
   semantics, one UnitBox, and topology descent.
2. Scheduler tests prove deterministic exhaustive registry order, balanced six
   scopes, and no named-reference identifiers.
3. Projection tests prove executable scope/principle nodes and typed rejection
   without unprojected fallback.
4. Count-100 integration proves 30/20/9 retained coverage, one UnitBox per
   candidate, explicit Matrix4 authority, morphology uniqueness, and existing
   family/capacity invariants.
5. Hybrid command tests prove cached and fresh sources traverse the identical
   normalization/projection boundary and persist the coverage ledger.
6. Only after all deterministic tests pass, run one zero-paid fresh pre-legal
   target-20 diagnostic and inspect its JSON ledger and board directly.

No statutory, parking, capacity, program, VLM, morphology, topology, or
diversity threshold is relaxed by this recovery.
