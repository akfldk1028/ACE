## Step 4: Projection Prototype

Status: panel-addressed prototype implemented.

Correct direction from MVPainter / Make-A-Texture / TexFusion:

- identify each exterior facade edge/plane.
- render/generate facade-specific front/right/back/left images with geometric
  control.
- project generated view panels back to the matching facade plane.
- avoid applying one global image to every wall.
- keep the legal orange MAAS mass as a toggle/overlay, not the primary visual
  when judging facade realism.

Immediate implementation target:

```text
provider generated multi-view sheet
-> crop front/right/back/left panels
-> assign panels to facade planes by normal/edge direction
-> Cesium wall ImageMaterialProperty per facade segment
-> close-up Playwright screenshot
```

Current result:

- GPT Image and Nano Banana both generate provider images, but direct atlas
  projection onto the stepped MAAS mass looked like repeated/collaged texture.
- Current VWorld bridge applies a cleaner structured facade canvas to the
  existing MAAS mass while retaining provider images as right-panel references.
- Provider outputs are now split into deterministic per-view panel assets and
  passed to the frontend as `texturePanelUrls`.
- Cesium facade materials use the matching view panel as a low-strength material
  seed under the structured facade grammar.
- `textureProbe=reference` is no longer the default Playwright path; real
  provider tests use `/design`.
- Aesthetic preview mode hides law-review envelope/reference layers while the
  facade is active.

Quality gate:

- Facade must read as a building, not a colored legal mass.
- Brick/glass/concrete material should show real-scale texture.
- Window rhythm should align with floors.
- Corners should not visibly conflict between adjacent facade planes.
- Procedural fallback is acceptable only as a no-key preview, not as the final
  photoreal result.

## Step 7: Real Mesh/UV Projection Worker

Status: deterministic atlas bake and mesh/glTF export implemented.

- Selected MAAS mass now exports a `projection_manifest.json` with stable facade
  surface IDs, vertices, UVs, triangles, and source panel views.
- The manifest lives in the same condition pack as `facade_planes.json`.
- Provider panel assets are now composed into `baked_texture_atlas.png`.
- `bake_manifest.json` maps the atlas back to projection surfaces.
- `textured_mesh_manifest.json` exports positions, UVs, indices, and per-surface
  ranges.
- `textured_mesh.gltf` exports the textured facade mesh with
  `baked_texture_atlas.png` as its material texture.
- Frontend now accepts `textured_gltf` and attempts to load it into VWorld using
  Cesium ENU transform from the MAAS origin.

Next implementation target:

- Playwright visual verification of the glTF-loaded facade in the actual
  `/design` VWorld viewport.
- Add validation images per facade.
- Validate:
  - no panel bleeding across corners,
  - floor datums align,
  - openings stay inside silhouette,
  - adjacent facade material color is consistent,
  - resulting asset can be reused outside VWorld.

This step moved the system from a VWorld preview material to a true 3D
texturing artifact. The remaining work is visual QA and higher-quality
multi-view texture refinement.
