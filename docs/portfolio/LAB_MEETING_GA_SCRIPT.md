## 슬라이드 1 — 직관의 정량화: 왜 유전 알고리즘인가?

> "매스 디자인을 자동화하려고 보니까, 단일 최적해가 없는 문제더라고요. 면적은 클수록 좋지만 일조는 줄어들고, 일조 확보하려면 매스를 후퇴시켜야 하니 면적이 줄고. 이런 *서로 충돌하는 목표가 여러 개*인 문제는 일반 최적화로 안 풀려요.
>
> 그래서 유전 알고리즘을 썼습니다. 진화 과정 흉내 낸 건데, 후보 매스를 *유전자처럼 숫자 벡터*로 만들어서 평가하고, 점수 좋은 것끼리 섞어서 다음 세대를 만드는 방식이에요. 특히 다목적용 변형인 NSGA-II는 *단일 최적해가 아니라 곡선*을 출력하는데, 이게 매스 문제에 정확히 맞는 도구입니다."

**키워드 강조**: *서로 충돌하는 목표* / *유전자처럼 숫자 벡터* / *단일 최적해가 아니라 곡선*

## 슬라이드 2 — 유전자 인코딩: 매스의 데이터화 규칙

> "매스 한 개를 알고리즘에 넣으려면 숫자 벡터로 바꿔야 돼요. 본 시스템은 매스 알고리즘 3종을 지원하는데, 인코딩이 다 다릅니다.
>
> *Additive*는 박스 5개 쌓는 방식이라 박스마다 위치·크기·회전 5개씩, 총 29개. *Subtractive*는 큰 블록에서 void 3개 빼는 방식으로 23개. *Grid*는 3×3 격자 9셀 on/off + 높이로 22개. 마지막 **4개 global gene**은 모든 알고리즘이 공유해요 — 층수, 회전, 상층부 축소, 단차 위치.
>
> 이렇게 인코딩하면 매스 한 개가 *숫자 벡터 한 개*가 되니까, 교배·돌연변이·평가가 다 숫자 벡터 위에서 처리됩니다."

**키워드 강조**: *Additive 29 / Subtractive 23 / Grid 22* / *Global 4 공유* / *벡터 위에서 처리*

## 슬라이드 3 — 4단계 진화 루프

> "여기가 GA 본체입니다. 네 단계가 한 세대고, 30세대 돕니다.
>
> 첫째, **Initialization** — 무작위로 30개 매스를 만들어요. 첫 세대는 평균 품질 낮지만 다양성 높아요. 둘째, **Evaluation** — 각 매스를 디코딩해서 면적·일조 같은 평가 함수에 넣고 점수 매깁니다. 셋째, **Selection** — 점수 높은 매스에 더 큰 확률로 부모 자격 줘요. 넷째, **Crossover + Mutation** — 부모 둘에서 유전자 일부 섞어 자식 만들고(crossover 0.9), 일부 무작위로 흔들어 변이(mutation 0.1).
>
> 이 사이클을 30번 반복하면 *30 × 30 = 900번 평가*. 마지막 세대 가면 첫 세대보다 평균 점수 훨씬 올라가 있고, 처음엔 못 봤던 좋은 매스가 발견돼 있습니다."

**키워드 강조**: *Init → Eval → Select → Cross/Mutate* / *900 evaluations* / *처음 못 봤던 매스 발견*

## 슬라이드 4 — NSGA-II 다목적 최적화

> "근데 평가가 한 숫자가 아니에요 — 면적이랑 일조 두 개. 그러면 어느 매스가 더 좋은지 비교가 안 됩니다. 면적은 큰데 일조 작은 매스랑, 일조는 큰데 면적 작은 매스 중에 누가 이긴 거냐는 거죠.
>
> NSGA-II가 이걸 두 가지 장치로 풀어요. 첫째, **Non-dominated Sorting** — *어떤 매스도 모든 점수에서 더 우월하지 않은* 매스들을 같은 그룹으로 묶어요. 이 그룹이 *Pareto front*입니다. 둘째, **Crowding Distance** — 같은 그룹 안에서도 서로 멀리 떨어진 매스를 우선 선택해요. 그래야 곡선이 한 점에 몰리지 않고 *전체에 고르게 분포*하거든요.
>
> 거기에 용도별로 평가 기준이 자동으로 바뀝니다. 주거·교육은 면적+일조, 상업·업무는 면적+조경, 문화시설은 면적+이격."

**키워드 강조**: *Non-dominated Sorting* / *Crowding Distance* / *용도별 동적 매핑*

## 슬라이드 5 — 파레토 프론트: 결정은 사용자가

> "최종 결과가 *단일 매스가 아니라 곡선*입니다. 가로축 면적, 세로축 일조 점수. 곡선 위 점들은 모두 의미 있는 매스예요. 한쪽 끝은 면적 극대 매스, 반대쪽은 일조 극대 매스, 중간은 균형 매스.
>
> 여기가 핵심인데, *알고리즘은 결정을 내리지 않아요*. 곡선만 그려줍니다. 어느 점을 고를지는 사업 목표에 따라 사용자가 직접 정해요. 면적 우선이면 한쪽 끝, 일조 우선이면 반대쪽, 균형 원하면 중간 클릭. 클릭하면 자동으로 3D 매스로 렌더링되고, 동시에 법규 위반 검증이 다시 돌아요. 위반 있으면 제약 5% 강화하고 GA 재실행하는 *생성-검증* 루프가 작동합니다.
>
> 정리하면, *법규가 envelope을 정의하고, GA가 envelope 안에서 매스 후보를 진화시키고, 사용자가 곡선 위에서 최종 선택*. 이 세 단계가 시스템 전체 흐름입니다."

**키워드 강조**: *알고리즘은 결정 안 함* / *사용자가 곡선 위에서 선택* / *생성-검증 루프*

## 자주 받을 수 있는 질문 4개 + 답변

### Q1. "왜 NSGA-II인가? 다른 다목적 GA도 많은데."
> "표준이고, 코드 라이브러리(`pymoo`)가 안정적이고, Pareto front를 잘 보존하는 게 강점이에요. 다른 알고리즘(SPEA2, MOEA/D)도 시도했는데 본 task suite에서는 NSGA-II가 가장 안정적이었습니다."

### Q2. "Population 30, Generations 30이면 작은 거 아닌가?"
> "맞습니다. 작은 부지에서는 충분한데, 큰 부지나 복잡한 envelope에서는 50 × 50까지 키웁니다. 작게 시작하는 이유는 *실시간성* — SSE 스트리밍으로 사용자에게 진행 상황을 즉시 보여주기 위해서요."

### Q3. "유전자 인코딩이 알고리즘별로 다르면 비교는 어떻게 하나?"
> "Polygon으로 디코딩한 다음의 평가 함수가 동일해서 비교 가능합니다. BCR, FAR, 일조, 이격, 조경 — 다 같은 함수로 점수 매깁니다."

### Q4. "사용자가 직접 선택하면 GA의 의미가 줄지 않나?"
> "오히려 반대예요. *결정 가능한 선택지*를 만드는 게 GA의 역할이고, 결정은 사람의 영역이에요. 단일 최적해를 강요하는 건 매스 디자인 본질에 안 맞아요. 면적이 우선인지 일조가 우선인지는 *사업 의사결정*이지 *기술적 최적화*가 아니거든요."
