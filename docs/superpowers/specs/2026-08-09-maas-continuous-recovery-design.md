# MASS Continuous Recovery Design

## Goal

Recover the production MASS pipeline so twenty genuine LLM-authored neighborhood masses can pass the existing legal, capacity, identity, semantic, parking, visual-diversity, and publishable-20 gates without producing a law-authored floor-stack phenotype.

## Causal authority

The only permitted geometry chain is:

`UnitBox -> authored base-form capability -> one authored global Matrix4 -> exact BOOK fraction/orientation/ordered operations -> typed CSG -> one fixed-pose site Matrix4 -> continuous legal-envelope CSG -> certified visual mesh`.

Law-derived floor plates measure GFA. They may not become the visible design language. A null unchanged-solid affine selector continues to the profiled continuous-envelope materializer; it is not a rejection and it does not authorize per-floor pose, aspect, or recentering.

## Recovery boundaries

- Preserve all existing user work and rejected C45-C52 evidence.
- Do not promote C50 or C52, mutate a rejected AST, weaken the 0.70 utilization floor, or add deterministic morphology fallback.
- Resume C53-B01 from its persisted eligible path set and exact request identity.
- Persist the raw OAuth response before parsing and package only validated typed AST programs in a trusted admission manifest.
- Replenish only measured deficits with fresh LLM authorship.
- Render the combined board only after twenty candidates pass production gates.

## Version memory

Every recovery run gets a unique version directory and immutable JSON snapshot containing run identity, parent version, request/artifact hashes, stage status, candidate counts, failure ledger entries, and output paths. The current numbered MASS memory remains the instruction authority; version snapshots are historical evidence and are never silently rewritten.

## Completion

Completion requires a passing publishable-20 manifest, twenty exact LLM-authored selected candidates, law/parking/final-mesh evidence, all pairwise diversity certificates, and an inspected combined PNG. Anything less remains diagnostic and does not change canonical `0/20`.
