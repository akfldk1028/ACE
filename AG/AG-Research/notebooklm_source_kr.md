# 멀티 에이전트 팀은 언제 멈춰야 하는가?
## 13가지 조정 토폴로지에서의 종료 역학 체계적 연구

---

## 연구 동기

LLM 기반 멀티 에이전트 시스템이 급속히 확산되고 있지만, "팀이 언제 멈춰야 하는가"라는 근본적 질문은 체계적으로 연구되지 않았다.

현재 사용되는 종료 기준은 세 가지다: 고정 턴 수(max_turns=10), 키워드 감지("TERMINATE"), 외부 타임아웃. 이 기준들은 에이전트의 조정 방식(토폴로지)과 무관하게 획일적으로 적용된다.

이로 인해 "종료 후회(termination regret)"가 발생한다:
- 과잉 종료: 합의 후에도 토론이 계속되어 토큰 낭비
- 과소 종료: 정제 단계 전에 중단되어 품질 손실
- 토폴로지 불일치: 잘못된 기준 적용으로 기능 손실

핵심 통찰: 최적 종료 시점은 에이전트의 조정 방식(토폴로지)에 근본적으로 의존한다.

---

## 선행 연구의 갭

Hu et al.(NeurIPS 2025)은 debate 전용 종료만 다루었고, REFRAIN(2025)은 단일 에이전트 CoT 전용이며, Aegean(2025)은 병렬 합의 전용이다. G-Designer(ICML 2025)는 토폴로지 선택을 최적화하지만 선택된 토폴로지 내에서 언제 멈출지는 연구하지 않았다. AgentDropout(ACL 2025)은 어떤 에이전트가 참여할지를 최적화하지만 언제 종료할지는 다루지 않는다.

다양한 토폴로지를 단일 통합 프레임워크에서 체계적으로 비교한 연구는 존재하지 않는다. 이것이 본 연구의 기회이다.

---

## 5대 기여

1. 교차 토폴로지 종료 비교: 13개 패턴, 4개 범주를 동일 프레임워크(AutoGen), 동일 모델(Claude Haiku 4.5), 동일 과제(20개)로 최초 체계 비교

2. 종료 후회 지표: G-Eval로 각 에이전트 턴마다 품질 점수를 매겨 턴별 품질 궤적을 구축하고, 품질이 정점에 도달한 시점과 팀이 실제 종료한 시점을 정밀 비교

3. 주장 수준 수렴 감지: Hu et al.의 KS-검정 접근법을 debate 전용에서 전체 13개 토폴로지로 확장하여 수렴 신호가 토폴로지 의존적임을 규명

4. 패턴별 오류 분류: MAST 오류 범주(환각, 불완전성, 불일치)와 정렬하여 오류 유형 분포가 토폴로지 특성과 상관함을 입증

5. 적응적 종료 메커니즘: U(t) = Q(t) - λ·C(t) 효용 기반 종료 기준 제안. REFRAIN의 판별기+UCB나 Aegean의 쿼럼 감지와 차별화되며, 토폴로지 인식 λ 튜닝을 도입

## 실험 설계

### 13개 패턴, 4개 범주 — 각 패턴의 동작 방식

범주 A (고정 순차): RR-2, RR-3, RR-4. 라운드 로빈 방식으로 고정 순서로 에이전트를 순환한다. 각 에이전트는 전체 대화 이력을 본다.
- 동작 예시 (RR-3): 사용자 질문 → Agent1 답변 → Agent2가 Agent1 답변을 보고 보완 → Agent3가 Agent1+2를 보고 종합 → Agent1이 다시 전체를 보고 수정 → ... (max_messages까지 반복)
- 핵심 특성: 모든 에이전트가 전체 대화를 읽어야 하므로 에이전트가 늘수록 입력 토큰이 급증한다.

범주 B (동적 라우팅): Sel-3, Sel-4, Swm-3, Swm-4. 조정자 에이전트(Selector 또는 Swarm)가 대화 상태를 기반으로 다음 전문가를 선택한다.
- Selector 동작: 조정자가 "이 질문에는 기술 전문가가 적합하다"고 판단 → 기술 전문가 호출 → 기술 전문가가 긴 독백으로 답변 → 조정자가 "이제 비즈니스 분석가의 관점이 필요하다" → 비즈니스 전문가 호출. 적은 턴(3~4)에서 깊은 답변 생성.
- Swarm 동작: Agent1이 답변 후 "이 부분은 Agent2가 더 잘 안다" → 핸드오프 → Agent2가 짧게 답변 후 다시 핸드오프 → ... 많은 턴(10~25)에서 짧은 교환. 각 에이전트는 자신에게 전달된 컨텍스트만 보므로 입력 토큰이 낮다.

범주 C (구조화 피드백): Refl-2, Refl-3, Deb-3, Deb-4.
- Reflection 동작 (Refl-2): 생성자가 초안 작성 → 비평가가 "이 부분이 부족하다, 이렇게 고쳐라" 피드백 → 생성자가 피드백 반영하여 수정안 작성 → 비평가가 "충분하다, 승인" 또는 추가 수정 요청. 생성-비평-수정 루프.
- Debate 동작 (Deb-3): 토론자A가 입장 제시 → 토론자B가 반론 → 토론자C가 다른 관점 → 중재자가 "A의 논거가 강하지만 C의 보완이 필요하다" 종합. 구조화된 논거 교환.

범주 D (복합/중첩): Pipe, MoA.
- Pipeline 동작: 과제 → 분석가(분석) → 연구자(심화) → 작성자(정리) → 비평가(검토) → 편집자(최종본). 각 단계의 출력이 다음 단계의 입력. 5에이전트가 순차적으로 처리.
- MoA 동작: 과제 → [기술 전문가 / 비평적 분석가 / 창의적 사고자] 3명이 동시에(병렬) 독립 응답 생성 → 집약자가 3개 응답을 종합하여 최종본 작성. 다양한 관점 확보.

### 5개 실험 (총 약 1,760회 실행)

실험 01 (패턴 효율): 13패턴 × 20과제 × 3반복 = 780회. 토폴로지별 비용(시간, 토큰, 턴 수) 비교.
실험 02 (종료 품질): 대표 패턴 5개(rr3, sel3, swm3, refl2, debate3) × 20과제 = 100회. 각 실행에서 매 턴마다 누적 응답을 Claude Sonnet 4.5(G-Eval judge)에게 보내 품질 점수 Q(t)를 5차원(정확성, 완전성, 일관성, 유용성, 종합)으로 평가한다. 이를 통해 "품질이 정점에 도달한 턴 t_optimal"과 "실제 종료 턴 t_actual"을 비교하여 종료 후회(R = t_actual - t_optimal)를 계산한다. **완료 (100/100, 276 턴 스코어)**.

실험 03 (수렴 감지): KS-검정으로 턴 간 의미적 안정성 추적. exp01 데이터 분석.

실험 04 (오류 귀인): 패턴별 오류 유형 분류. exp01 데이터 분석.

실험 05 (적응적 종료): U(t)=Q(t)-λC(t) 검증. 대표 패턴 6개 × λ 5개(0.0, 0.05, 0.1, 0.2, 0.5) × 20과제 = 600회. λ=0.0은 "품질만 추구(비용 무시)", λ=0.5는 "비용 민감(일찍 멈춤)". 토폴로지별 최적 λ가 다름을 입증하고, 고정 종료 기준(max_messages, keyword) 대비 파레토 프론티어 개선을 검증한다.

### 실험 인프라 및 실행 파이프라인

프레임워크: Microsoft AutoGen v0.4 (멀티 에이전트 오케스트레이션)
커스텀 모델 클라이언트: ClaudeCLIChatCompletionClient (AutoGen의 ChatCompletionClient 인터페이스를 구현하되, 내부적으로 Claude CLI SDK를 호출하여 Anthropic API와 통신)
기반 모델: Claude Haiku 4.5 (모든 에이전트 동일 모델, 일관성 확보)
평가 모델: Claude Sonnet 4.5 (G-Eval judge, exp02/05에서 품질 평가용)
과제: 20개 (사실형 5, 창의형 5, 분석형 5, 기술형 5) × 3반복
지표: 지속시간(초), 턴 수, 토큰(입력/출력), 에러율, 품질점수

#### 실험 실행 흐름 (하나의 실행 단위)

1단계 — 팀 생성: TeamFactory.build(pattern, max_messages) 호출. 패턴 이름(예: "rr3", "sel4", "debate3")을 받아 AutoGen의 RoundRobinGroupChat, SelectorGroupChat, Swarm, 또는 커스텀 ReflectionTeam/DebateTeam/PipelineTeam/MoATeam을 생성한다. 각 팀에는 패턴에 맞는 에이전트(AssistantAgent)들이 배치되고, 모든 에이전트는 동일한 ClaudeCLIChatCompletionClient를 모델로 사용한다.

2단계 — 팀 실행: ExperimentRunner.run_single(team, task_text)이 team.run(task=task_text)을 호출한다. AutoGen 프레임워크가 패턴의 규칙에 따라 에이전트 간 대화를 조정한다. 예를 들어 RoundRobin은 고정 순서로 발언권을 순환하고, Selector는 조정자가 다음 발언자를 선택하고, Debate는 토론자들이 번갈아 논거를 교환한다.

3단계 — 종료: 대화가 종료 조건(max_messages 도달, "TERMINATE" 키워드 감지, 또는 패턴 고유 조건)을 만족하면 멈춘다.

4단계 — 결과 수집: RunResult에 duration_sec, total_tokens_in, total_tokens_out, turn_count, stop_reason, 각 턴의 텍스트를 기록한다. CSV(요약)와 JSON(전체 대화 원문)으로 저장한다.

5단계 (exp02만 해당) — 품질 평가: 각 턴의 누적 응답을 Claude Sonnet 4.5에게 보내 G-Eval 5차원 점수(정확성, 완전성, 일관성, 유용성, 종합)를 1~5점으로 매긴다. 이를 통해 턴별 품질 궤적 Q(t)를 구축한다.

#### 왜 이 방식인가?

핵심 설계 원칙은 "통제된 비교"이다. 13개 토폴로지를 공정하게 비교하려면 (1) 동일 LLM, (2) 동일 과제, (3) 동일 프레임워크에서 실행해야 한다. 기존 연구들은 대부분 단일 토폴로지(예: debate만)를 특정 벤치마크에서 평가하여 토폴로지 간 비교가 불가능했다. 본 연구는 AutoGen의 다양한 팀 패턴 지원을 활용하여 이 문제를 해결한다.

ClaudeCLIChatCompletionClient는 AutoGen의 표준 ChatCompletionClient 인터페이스를 구현하면서 내부적으로 Claude CLI SDK를 호출한다. 이를 통해 AutoGen의 모든 팀 패턴(RoundRobin, Selector, Swarm, 커스텀 팀)을 수정 없이 사용하면서 Anthropic 모델을 백엔드로 활용할 수 있다.

#### 과제 설계

20개 과제는 4가지 범주로 설계했다:
- 사실형 5개: 단일 정답이 존재하는 팩트 질문 (예: "양자 컴퓨팅의 DiVincenzo 기준 5가지를 설명하라")
- 창의형 5개: 열린 결말의 창작/설계 과제 (예: "시간 여행 역설을 해결하는 SF 단편의 플롯을 설계하라")
- 분석형 5개: 비교/분석/추론 과제 (예: "원격근무가 소프트웨어 팀 생산성에 미치는 영향을 분석하라")
- 기술형 5개: 코드/시스템 설계 과제 (예: "분산 캐시 시스템의 일관성 프로토콜을 설계하라")

각 범주는 에이전트 팀에 다른 부하를 가한다: 사실형은 빠른 수렴(정답 도달 후 멈춤), 기술형은 긴 응답(코드 포함), 창의형은 다양한 해석 가능성으로 수렴이 어려움.

#### 체크포인트 및 재현성

모든 실험은 체크포인트 시스템을 갖추어, 중단 시 마지막 완료된 지점부터 재개할 수 있다. 결과는 패턴별·범주별로 분리 저장(summary_A.csv, summary_B.csv 등)하여, 하나의 범주가 실패해도 다른 범주의 데이터가 유실되지 않는다. 최종적으로 merge_results.py로 전체 780회 데이터를 단일 summary_all.csv로 병합한다.

## 범주 A 결과: 고정 순차 (Round-Robin)

RR-2 (2에이전트): 평균 52.4초, 4,759 토큰, 출력/턴 1,583, 에러율 8.3%
RR-3 (3에이전트): 평균 96.6초, 10,121 토큰, 출력/턴 1,711, 에러율 23.3%
RR-4 (4에이전트): 평균 118.8초, 12,040 토큰, 출력/턴 1,942, 에러율 71.7%

발견 1 — 협력적 증폭(Collaborative Amplification): 에이전트를 추가하면 비용은 약 2배(준선형)로 증가하지만, 호출당 출력 토큰은 오히려 증가한다. 사실형 과제만 비교하면 rr2=930, rr3=1,189, rr4=1,544 토큰/호출. 에이전트가 더 풍부한 컨텍스트에서 더 풍부한 응답을 생성하는 현상이다.

발견 2 — 입력 토큰 초선형 증가: 입력 토큰이 2.59배 증가하는 반면 LLM 호출은 1.75배만 증가했다. 각 에이전트가 전체 대화 이력을 읽어야 하기 때문이다. 비용의 주 동인은 이 컨텍스트 복사 비용이다.

발견 3 — 오류율 초선형 증가: rr2는 기술형 과제에서만 오류(8.3%), rr3는 창의형+분석형+기술형 3개 범주로 확산(23.3%), rr4는 사실형을 제외한 전 범주에서 실패(71.7%). 컨텍스트 축적이 팀 규모에 따라 한계를 초과한다.

발견 4 — 과제 범주 효과: 창의형이 가장 오래 걸리고(93.3초), 기술형이 가장 많은 토큰을 사용하며(9,100), 사실형은 에러가 0%이다.

## 그래서 "언제 멈춰야 하는가?" — exp01에서 발견한 종료 신호

본 연구의 핵심 질문은 "멀티 에이전트 팀이 언제 대화를 멈춰야 하는가"이다. exp01의 효율 데이터는 직접적인 최적 종료 시점(이것은 exp02에서 품질 궤적을 측정하여 확인)을 제시하지는 않지만, 각 토폴로지가 가진 고유한 종료 신호와 종료 실패 패턴을 드러낸다.

### 토폴로지별 종료 신호 (exp01에서 관찰)

범주 A (고정 순차) — 종료 신호가 없다: Round-Robin은 자체적인 수렴 메커니즘이 없다. 에이전트들은 고정 순서로 계속 발언하며, "충분히 좋은 답"에 도달했는지 판단하지 못한다. 현재는 max_messages 한도에 도달해서 강제로 멈추는 것이 유일한 종료 수단이다. 이것이 바로 "토폴로지 인식 종료"가 필요한 이유다. 순차 패턴에는 외부 품질 감시자(exp05의 U(t) 메커니즘)가 필수적이다.

범주 B (동적 라우팅) — 라우팅 안정화가 종료 신호: Selector 패턴에서 조정자가 같은 전문가를 반복 선택하기 시작하면 "더 이상 새로운 전문가가 필요 없다"는 수렴 신호다. Swarm에서 핸드오프 빈도가 급증(swm4에서 10→25턴 폭발)하면 이는 "에이전트들이 합의에 실패하고 있다"는 경고 신호로, 조기 종료가 오히려 바람직하다. swm4의 턴 폭발은 종료 기준이 "대화가 길어지면 계속하라"가 아니라 "핸드오프가 급증하면 멈춰라"여야 함을 보여준다.

범주 C (구조화 피드백) — 자연적 수렴 신호가 존재한다: Debate에서 에이전트당 출력이 감소(deb3=1,691→deb4=1,448 토큰/턴)하는 현상은 "더 이상 새로운 논거가 없다"는 수렴 신호다. 토론자들의 발언이 짧아지면 합의에 근접한 것이다. Reflection에서 비평가의 수정 요청이 줄어들거나 "승인(approve)" 판정을 내리면 품질이 충분하다는 종료 신호다. 이런 자연적 수렴 신호가 있기 때문에 피드백 패턴에서는 높은 λ(일찍 멈추는 것)가 허용된다.

범주 D (복합) — 단계별 종료가 필요하다: Pipeline은 각 단계의 출력이 다음 단계의 입력이 되므로, 전체 파이프라인에 단일 max_turns를 적용하면 안 된다. 첫 단계(분석)와 둘째 단계(종합)의 최적 턴 수가 다르다. MoA는 병렬 제안자들이 모두 완료된 후 집약하므로, "가장 느린 제안자"가 전체 지연을 결정한다. 종료 기준은 개별 제안자 레벨과 집약자 레벨에서 각각 다르게 설정해야 한다.

### 현재 데이터의 한계와 후속 실험

exp01은 "토폴로지별 비용 구조와 스케일링 특성"을 규명하여, 왜 획일적 종료 기준이 문제인지를 입증하고, 각 토폴로지의 고유한 종료 신호를 식별했다.

그러나 "RR-3는 정확히 턴 X에서 멈추는 것이 최적이다"와 같은 구체적 최적 종료 시점은 exp02(G-Eval 턴별 품질 궤적)에서 확인한다. exp02는 매 턴마다 품질 점수 Q(t)를 측정하여, 품질이 정점에 도달한 시점 t_optimal과 팀이 실제 종료한 시점 t_actual의 차이(종료 후회 R = t_actual - t_optimal)를 계산한다.

exp05(적응적 종료)에서는 U(t) = Q(t) - λ·C(t) 메커니즘이 실제로 고정 종료 기준 대비 품질-비용 파레토 프론티어를 개선하는지를 720회 실험으로 검증한다.

요약하면: exp01은 "왜 토폴로지 인식 종료가 필요한가"를 증명했고, exp02/05는 "구체적으로 어떻게 멈춰야 하는가"를 답한다.

### 세 가지 품질 궤적 유형 (발견 15)

**유형 1 — 단조 증가 후 정체(Monotonic-then-plateau)**: rr3가 대표적이다. 턴 1에서 3.8점, 턴 3에서 4.35점으로 상승한 후 턴 6까지 4.3~4.4에서 정체한다. 추가 턴이 품질을 거의 개선하지 않지만 악화시키지도 않는다. 과잉 계산에 의한 품질 손실이 0.05점에 불과하다.

**유형 2 — 턴 2 정점 후 유지(Peak-at-turn-2)**: refl2가 대표적이다. 생성자의 초안(턴 1)이 3.9점이면, 비평가의 수정 후(턴 2) 4.80점으로 급등하고 이후 유지된다. 비평가의 "승인(APPROVED)" 신호가 정확히 최적 종료 시점과 일치한다. 종료 후회가 0이다.

**유형 3 — 단조 하락(Monotonic-decline)**: debate3가 대표적이다. 턴 1에서 4.0점의 정점을 찍은 후 턴 3~4에서 3.35점으로 하락한다. 토론이 길어질수록 품질이 악화된다. 과잉 계산에 의한 품질 손실이 0.65점으로 전 패턴 중 최대이다.

### 반성이 최고 품질 + 제로 후회를 달성 (발견 17)

refl2는 유일하게 t_actual ≈ t_optimal인 토폴로지이다. 비평가의 "APPROVED" 신호가 신뢰할 수 있는 자연적 종료 신호로 기능한다. 반면, debate3의 "VERDICT" 신호는 너무 늦게 도착하여 — 이미 품질이 하락한 후에야 종료된다.

sel3는 첫 턴에서 높은 품질(4.0)을 달성하지만, 추가 턴에서 0.50점이 하락한다. 선택자가 추가 전문가를 불필요하게 호출하여 오히려 답변을 희석시키는 현상이다.

### 교차 범주 통계 분석 (Kruskal-Wallis, 발견 18-20)

780회 전체 데이터에 Kruskal-Wallis 검정 적용. 턴 수(H=314.6), 지속시간(H=69.0), 총 토큰(H=204.3) 모두 p<0.001로 범주 간 고도 유의차 확인.

발견 18 — 동적 라우팅(B)과 구조화 피드백(C)은 토큰 비용에서 통계적으로 구분 불가능(Mann-Whitney p=0.112). 중앙값이 거의 동일(B: 9,174 vs C: 9,247). 조정 메커니즘이 근본적으로 다른데도 비용이 수렴.

발견 19 — 4단계 비용 위계: A(4,010) ≪ B≈C(~9,200) ≪ D(15,865). 최저/최고 범주 간 3.95배 격차.

발견 20 — 에이전트 수의 영향이 토폴로지에 따라 극적으로 다름. 범주 C에서 강한 상관(ρ=0.805, p<0.001), 범주 B에서 중간(ρ=0.324), 범주 A에서 비유의(ρ=−0.132, p=0.078). A의 반직관적 결과는 rr4의 71.7% 오류율이 조기 종료를 유발하여 양의 상관을 가렸기 때문.

## 오리지널 기여: 효용 기반 적응적 종료

제안 수식: U(t) = Q(t) - λ · C(t)

Q(t)는 턴 t에서의 품질(G-Eval 5차원 점수), C(t)는 정규화된 누적 토큰 비용, λ는 품질-비용 트레이드오프 계수이다.

종료 조건: U(t) < U(t-1)이면 멈춘다. 즉, 한계비용이 한계품질이득을 초과하면 종료한다.

핵심 차별점은 토폴로지 인식 λ 튜닝이다:
- 피드백 패턴(범주 C): 높은 λ 허용. 자연 수렴 신호가 있어 일찍 멈춰도 품질 유지.
- 순차 패턴(범주 A): 낮은 λ 필요. 수렴 신호가 없어 조기 종료 시 품질 손실.
- 동적 라우팅(범주 B): 중간 λ. 조정자 오버헤드를 비용에 포함해야 공정.

기존 연구와의 비교: REFRAIN은 단일 에이전트 CoT 대상으로 판별기+UCB 방법을 사용하며 λ가 고정이다. Aegean은 병렬 합의 대상으로 쿼럼 감지를 사용한다. 본 연구는 13개 토폴로지 전체를 대상으로 효용함수 U(t)를 사용하며 토폴로지 인식 λ 튜닝을 도입한다.
